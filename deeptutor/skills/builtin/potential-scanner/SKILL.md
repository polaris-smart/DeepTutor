# 提分空间评测器

把“哪里薄弱”转换成“先补哪里最划算”。评测需要在乐观与保守之间保持可解释：预计分数只能来自本次真实丢分，mastery 只能说明当前掌握，知识类型只调节补救速度，三者不能互相冒充。

开始后调用 `read_skill(name="potential-scanner", file="references/template.md")`，把模板当作唯一输出合同。

## 第一步：读取并核对输入

接受两种入口：

1. **诊断入口**：读取上游 `score-diagnosis` 的 `deeptutor_handoff`、考试概览和“接力数据”表。优先使用 `knowledge_point`、`max_score`、`lost_score`、`knowledge_type`、`mastery`、`related_q_ids` 和 `primary_error`，不要从散文段落重新猜数。
2. **mastery 入口**：直接读取当前范围的 mastery 数据。保留知识点名称或 ID、类型、状态与 mastery 数值；没有丢分数据时仍可排修补顺序，但不能估算可回收分数。

核对规则：

- 诊断入口沿用上游的 `subject`、`textbook`、`scope`、`student` 和日期；不要改变学生或把不同范围的报告拼在一起。
- mastery 与诊断同时存在时，先以模块名限定当前范围，再按稳定知识点 ID 精确连接；没有 ID 时只接受唯一的规范化名称匹配。多个候选或模糊匹配时写“未匹配”，不自行任选。
- mastery 可为 `0..1` 或 `0..100`，展示时统一成百分比；状态值 `new`、`learning`、`mastered` 原样保留。没有 mastery 时，若上游有知识点满分和丢分，可补充“本卷得分率”，但必须标明这不是长期 mastery。
- 上游题型表与接力数据有冲突时，以逐题明细重新核算；无法核算时停止计算预计分数，展示冲突项。

## 第二步：确定提升难度

使用 `deeptutor/learning/models.py` 的知识类型语义，不把它们与 `ErrorType` 混用：

| knowledge_type | 提升难度 | 回收系数 | 判断含义 |
| --- | --- | ---: | --- |
| `memory`（记忆型） | 快 | 0.8 | 短周期复习与提取练习通常能回收较多本次丢分 |
| `concept`（概念型） | 中 | 0.6 | 需要纠正概念关系并用题目验证 |
| `procedure`（程序型） | 慢 | 0.4 | 需要分步练习形成稳定步骤 |
| `design`（设计型） | 慢 | 0.4 | 需要综合构造与反馈；保留模型已有类型，不强行塞入前三类 |

缺少或无法确认 `knowledge_type` 时，难度与预计可回收分数均写“待确认”；不要根据学科或知识点名称擅自定型。

## 第三步：计算分数空间与优先级

诊断入口按以下固定口径计算：

1. `预计可回收分数 = lost_score × 回收系数`，四舍五入到 1 位小数，并限制在 `0..lost_score`。这是基于本次卷面与知识类型的规划估算，不是成绩承诺。
2. 给难度设置成本：快 = 1、中 = 2、慢 = 3；计算内部排序值 `预计可回收分数 ÷ 成本`。
3. 只给 `lost_score > 0` 的行按排序值降序排列；并列时先比较 `lost_score`，再比较知识点名称，保证同一输入产生稳定顺序。优先级依次写 `P1`、`P2`、`P3`……；本卷未丢分的行写“—”。
4. `mastery` 只用于解释和校验，不暗改预计分数。出现“mastered 但本卷大量丢分”时提示检查审题、迁移或 mastery 新鲜度；不要直接覆盖任一来源。
5. 总预计回收分数为所有有可靠 `lost_score` 与类型的行之和；另列因类型未知而未计入的丢分，不能把它们默认为 0 或概念型。

只有 mastery、没有卷面丢分时：

1. 用 `掌握缺口 ÷ 成本` 排序；数值 mastery 的掌握缺口为 `1 - mastery`，状态仅有 `new/learning/mastered` 时按该状态顺序排序，同状态再按难度快→中→慢。
2. “丢分”和“预计可回收分数”写“—”，优先级仍可给出。
3. 总判断必须写“预计增分待补逐题分值后计算”，不得把 mastery 百分比换算成分数。

## 第四步：输出矩阵与一句话判断

1. 严格套用 `references/template.md`，输出标准 header、口径说明、分数空间矩阵和一句话总判断。
2. header 七字段顺序与 `pre-exam-checklist` 一致。`upstream` 写 `score-diagnosis:<真实产物标识>` 或 `mastery_status`；缺少产物标识时只写 `score-diagnosis`，不编造 ID。
3. 考试临近或用户明确说“考前”时，`suggested_downstream` 写 `pre-exam-checklist`；平时练习场景写“题感训练”；场景不明确时写 `pre-exam-checklist（考前） / 题感训练（平时）`。
4. 一句话必须使用：`最优路径：先攻 X，再攻 Y，预计 +Z 分。` 只有一个可评估知识点时删去“再攻 Y”；没有分值依据时改为：`最优路径：先攻 X，再攻 Y；预计增分待补逐题分值后计算。`
5. 完成矩阵后停止。除非用户明确要求，不自动生成考前清单或训练题。

## 异常与降级

- 上游 header 缺字段：用报告正文中可证的信息补齐；仍缺失时写“未提供”，不因 header 不完整丢弃真实数据。
- 上游范围或学生与 mastery 不一致：停止合并，列出冲突字段，请用户选择正确数据集。
- 接力数据没有知识点：无法生成知识点矩阵，退回 `score-diagnosis` 补齐归属。
- 只有总丢分、没有知识点分配：不把总分均摊到知识点；说明缺少逐题归属。
- 所有知识类型都未知：可以展示丢分和掌握情况，但不生成虚假的难度、预计回收分数与 `+Z`。
