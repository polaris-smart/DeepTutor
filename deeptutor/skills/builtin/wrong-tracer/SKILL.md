# 错题归因追分器

把“这道题错了”变成“这个错因值得花多少力气、做哪几道题来补”。归因的张力在于“果断分类”与“不把分数猜成性格”：证据足够时明确归类，证据不足时保留“待确认”，不要用看似专业的错因填满每一行。追分动作必须具体到题目，预计回收分只是规划估算，不是成绩承诺。

开始后调用 `read_skill(name="wrong-tracer", file="references/template.md")`，把模板当作归因报告的输出合同。完成归因报告后停止，不自动生成题型卡或考前清单。

## 第一步：接收并规范错题输入

1. 接收两类输入：
   - **错题本条目（question_notebook）**：优先使用条目中的真实字段：`question_id`（即 q_id）、`question`、`question_type`、`user_answer`、`correct_answer`、`explanation`、`is_correct`、`difficulty`、`ai_judgment` 与 `categories`。只使用真实存在的 `question_id`；没有时写“题号 N”或“未提供”，不伪造 q_id。
   - **学生口述错题**：转录题干、学生作答与标准答案（若提供）；不确定处标“待确认”。
2. 逐条判断 `is_correct`：只归因 `is_correct: false` 或口述明确答错的题；答对的题不进入追分计划。
3. 缺少题干、作答或正确答案时保留缺口，先做能做的归因；无法归因的条目单列“待补充”，不猜错因。

## 第二步：错因三分法归类

1. 对每条错题先用“三分法”给用户易读错因，再按下面的映射给出规范 `ErrorType`（引用 `deeptutor/learning/models.py` 语义）：

| 三分法 | 用户含义 | 证据特征 | 规范 `ErrorType` |
| --- | --- | --- | --- |
| 知识性 | 概念不清 | 前置知识缺口、定义或关系未建立 | 知识网络缺口用 `structural`；知识存在但理解偏移用 `deviation` |
| 方法性 | 思路错 | 论证链、迁移步骤或方法选择出现断点 | 理解链偏移用 `deviation`；理解正确但落地步骤错用 `application` |
| 习惯性 | 计算审题马虎 | 列式方向正确但运算、符号、单位或代入出错；漏条件、看错要求且不是知识不会 | 计算类用 `application`；审题类用 `metacognitive` |

2. 证据优先级：判卷器或老师明确标签 → 可见作答与参考过程 → `ai_judgment` → 只有对错结果。只有“做错了”不能证明错因。
3. 每条错题只能选一个主要三分法错因和一个主要 `ErrorType`；多个因素并存时把次因写进证据说明，不重复计题。
4. 证据不足时写“待确认”，并给出最短确认问题（如“是公式不会，还是代入后算错？”），不按题型刻板推断。
5. 六维能力快照（`knowledge`/`procedure`/`understanding`/`transfer`/`retention`/`habit`）是与 `ErrorType` 独立的一套语义：只引用 `data_state: scored` 且有 `evidence_refs` 的维度结果作为补充证据，不把维度名直接当成 `ErrorType`，`insufficient` 不包装成能力结论。

## 第三步：挂追分动作

1. 每条错因生成一条“追分动作”，必须具体到**做哪 3 道同考点题**，并给出顺序与复盘方法：
   - 先重做本题：优先引用本条目的真实 `question_id`；
   - 再补 2 道同类题：只在当前已挂载的题目检索能力中按同一考点找题，仅采用真实返回的题目节点与 `q_id`，标明“同类补题”；
   - 检索不到时写 `待补题（缺 N 个 q_id）` 并描述建议题型与考点，让老师补充；不用题号、模型生成题或虚构字符串冒充 q_id。
2. 同一个 q_id 不得在同一动作内重复；跨动作确需复用时说明它分别训练哪个步骤。
3. 每个动作写一句可观察的完成标准，例如“3 题全对并能口述漏条件检查”。

## 第四步：汇总追分计划表

1. 输出“错因 → 动作 → 预计回收分”计划表，每个动作一行。
2. 预计回收分口径（与 `potential-scanner` 一致，仅规划估算）：
   - 有上游丢分数据（判分或 `score-diagnosis` 接力数据）时，`预计回收分 = 丢分 × 回收系数`，回收系数按知识类型：记忆型 0.8、概念型 0.6、程序型/设计型 0.4，四舍五入到 1 位小数且不超过该题丢分；
   - 没有丢分数据时写“—”，并注明“待判分后估算”，不把题数、难度或主观感觉换算成分数。
3. 每个动作标注预计回收分是规划估算，不是成绩承诺；精确分数空间由 `potential-scanner` 评估。
4. 按“预计回收分 × 可补救度”把动作排成建议执行顺序；没有分数依据时按错因可补救度排序（习惯性孤立失误 > 方法性局部断点 > 知识性结构缺口）。

## 第五步：输出归因报告

1. 严格套用 `references/template.md`：标准 `deeptutor_handoff`、错题清单与归因表、追分计划表、口径与待补项。
2. header 七字段顺序与 `pre-exam-checklist` 一致；`upstream` 写 `question_notebook:<条目 id>`（没有 id 时只写 `question_notebook`）或 `student_statement`；`suggested_downstream` 固定为 `type-cards / pre-exam-checklist`。
3. 输出后做硬检查（见模板），确认每个追分动作都有 3 个真实 q_id 或明确的待补缺口。
4. 报告完成后停止。用户说“做题型卡”或“做考前清单”时再接力到对应下游，不自动触发。

## 异常与停止条件

- 输入只有对错、没有作答与任何反馈：错因保留“待确认”，追分计划表只给补题动作、不给错因结论。
- 错题本条目没有 q_id：保留题号或条目 id，不编造 q_id。
- 题目检索能力不可用或检索为空：动作写待补缺口并描述建议题型，不生成假题目。
- 没有丢分数据：预计回收分写“—”，不估算分数。
- 完成归因报告后停止。除非用户明确要求，不自动运行 `type-cards`、`pre-exam-checklist` 或生成训练题。
