# 题型提分卡

把同一题型的零散错题压成一张“下次见到就能套”的方法卡和一副可翻的卡组。提纯的张力在于“概括到能用”与“不脱离错题证据”：套路、易错点与口诀必须能从错题集或范围素材中找到出处，素材不足时不凑数；JSON 必须严格符合 Book Engine 的 flash_cards block schema，字段与长度一旦写错前端就无法渲染。

开始后调用 `read_skill(name="type-cards", file="references/template.md")`，把模板当作方法卡与 JSON 的输出合同。

## 第一步：接收并聚合错题集

1. 接收两种入口：
   - **上游 wrong-tracer 归因报告**：读取其 `deeptutor_handoff`、错题清单与追分计划表，按题型聚合；沿用上游的学科、范围与错因信息。
   - **直接给定“题型 + 范围”**：从用户表达中提取题型与范围（如“二次函数应用题”“立体几何证明题”）；有教材上下文时可按范围定位素材。
2. 判断该题型下错题的数量与错因分布：错题少于 3 道时说明素材不足，仍可给方法卡骨架但必须标注“待更多错题验证”；没有错题只有题型名称时，先向用户确认素材来源，不凭空总结套路。
3. 确定知识类型与高频错因，作为方法卡“易错点”的证据来源。

## 第二步：提炼方法卡

1. **核心套路 3 步**：把该题型最稳定的解法主干压缩成恰好 3 步，每步是一个动作短句（如“建系 → 设点 → 用距离公式列方程”）。步骤之间要能串成完整流程，不能是 3 个并列技巧。
2. **关键易错点 2 条**：从错题集的错因中选出最高频的 2 条，每条写成“❌ 常见错误做法，正确做法（为什么错）”。
3. **口诀 1 句**：把 3 步套路压成一句可背诵的口诀，不超过 20 个汉字。
4. 所有内容必须能由错题集或范围素材支持；素材不足时在方法卡上标注“依据 N 道错题提炼，待更多样本验证”。

## 第三步：生成 flash_cards block JSON

1. 先按 `deeptutor/book/blocks/flash_cards.py` 的 schema 核对字段，再生成 JSON：
   - 顶层键为 `cards`，值为数组；每张卡是 `{"front": ..., "back": ..., "hint": ...}`；
   - `front` = 题干特征（看到什么特征用这招），必填、非空、≤300 字符；
   - `back` = 方法要点（套路步骤/易错点/口诀），必填、非空、≤600 字符；
   - `hint` = 翻卡前的提示语，可空、≤200 字符；
   - 每副卡组 3-8 张卡；顶层可附可选 `_metadata` 字典（如题型、范围），无则省略。
2. 卡面内容直接从第二步的方法卡拆解：正面是“题干特征”，反面是“方法要点”，不把完整题目或完整解答写进卡面。
3. 生成后逐字段核对：front/back 非空且不超长、hint 不超长、张数在 3-8 之间、JSON 语法合法。用字符数而非字数统计。

## 第四步：给在线翻卡与打印两用建议

1. **在线翻卡**：说明该 JSON 可直接作为 Book Engine `flash_cards` block 的 `cards` 数据——先看 `front`（题干特征）判断题型，必要时点开 `hint`，翻面核对 `back`（方法要点）；建议按错题顺序从高频错因卡开始翻。
2. **打印两用**：给 A4 打印建议——把每张卡的 `front` 与 `back` 排成两栏卡片（正面一栏、反面一栏，或正反对应），复用 `pre-exam-checklist/references/print-css.md` 的打印骨架；卡片高度固定、每行 2-3 张，保证正反面切分后能对齐。
3. 两用建议只是说明，不默认生成打印文件；用户明确要 A4 打印版时再调用打印流程。

## 第五步：输出方法卡与 JSON 示例

1. 严格套用 `references/template.md`：标准 `deeptutor_handoff`、方法卡（3 步套路 + 2 条易错点 + 1 句口诀）、flash_cards JSON 示例、两用建议。
2. header 七字段顺序与 `pre-exam-checklist` 一致；`upstream` 写 `wrong-tracer:<报告标识>`、`question_notebook` 或 `teacher_statement`；`suggested_downstream` 固定为 `mastery quiz（练）`。
3. JSON 示例必须在报告中完整给出，并在其后附字段核对表。
4. 输出后做硬检查（见模板），确认 JSON 与 flash_cards.py schema 一致。
5. 完成方法卡后停止。用户说“开始练”或进入练习流程时，再接力到 `mastery quiz`，不自动触发。

## 异常与停止条件

- 错题少于 3 道或只有题型名称：说明素材不足，可给骨架但标注“待验证”，不生成看似完整的套路。
- 上游归因报告缺范围或学科：沿用其 header，缺失字段写“未提供”。
- JSON 校验失败（字段缺失、超长、张数越界、语法错误）：修正后重新核对再交付，不交付非法 JSON。
- 完成方法卡与 JSON 后停止。除非用户明确要求，不自动进入练习或生成考前清单。
