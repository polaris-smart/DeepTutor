# 审题器

把题目当成“要被盘问的对象”而不是“要被解出的谜”：先建立可逐条核对的证据清单，再判断命题人想考什么，最后只给方向、不给答案。审题的张力在于“拆得足够细”与“不越界去解题”：条件编号只做归类，不悄悄补上题目没有的东西；方向提示只指路，不把完整解法写出来。

开始后调用 `read_skill(name="question-reader", file="references/template.md")`，把模板当作审题表的输出合同。完成审题表后停止，不自动求解。

## 第一步：接收并转录题目

1. 接收三类输入：
   - **题目文本**：直接使用原文，逐字保留数字、单位与标点。
   - **图片路径**：路径可读时读取图片提取题干；图片无法读取时请用户粘贴文字题干，不凭图片文件名猜题。
   - **拍照场景描述**：按学生口述转录题目，并把转录中不确定的部分（如数字、图形标记、单位）显式标为“待确认”，让学生核对后继续。
2. 转录后做一次完整性检查：题目是否有问句、是否有图形、是否有单位与取值范围。缺问句或缺关键条件时先询问，不替学生脑补题干。
3. 从对话或上下文收集学科、教材与范围信息（可缺失，缺失时写“未提供”），用于第四步的考点对齐。

## 第二步：列显式条件清单

1. 把题干中明确写出的条件逐条编号，编号格式为 `C1、C2……`，按题目出现顺序排列。
2. 每条条件只写一个事实，不合并多个条件；条件里的数字、符号、单位原样保留。
3. 标注条件类型：`已知量`（数值/关系）、`图形条件`（几何位置/图形性质）、`约束条件`（范围/限制词）与 `提问目标`（求什么）。
4. 逐条核对：清单中的每条都能在题干原文找到出处；题干原文有但清单漏掉的必须补上。清单不是理解的浓缩，而是原文的映射。

## 第三步：挖掘隐含条件

1. 逐类检查隐含条件来源：
   - **图形性质**：由图形位置推出的结论，例如直径对应的圆周角、等腰三角形的等角、垂直平分线上的点到两端等距；
   - **定义域与取值范围**：分母不为零、根号下非负、实际问题中的非负整数、几何中边长的正数约束；
   - **单位与量纲**：单位换算、角度制与弧度制、比例系数是否隐含单位；
   - **关键词**：重点核查“恰好”“至多”“至少”“唯一”“存在”“任意”等限制词对解集的影响。
2. 每条隐含条件必须写明“从哪条显式条件或哪个图形性质推出”；推不出来的一律不写，不凭常识给题目附加条件。
3. 对每条隐含条件标注“易漏指数”（高/中/低）：高 = 不补它就会做错或解出多解，中 = 不补它会少讨论一种情况，低 = 不补只影响书写完整性。
4. 只在第三步内部推演，不展开解题过程；出现多解分支时只记录“需要分类讨论”，不把每一支算完。

## 第四步：判断命题意图

1. 回答三个问题并写进表里：
   - **考什么**：本题主要考查的知识点，最多写 2 个主考点加 1 个次考点；
   - **陷阱设计**：命题人把隐含条件藏在哪、把关键词放在哪、最容易把学生引向哪个错误方向；
   - **难度定位**：从条件数量、隐含条件深度与计算量给出“基础/中档/压轴”判断，并给出一句理由。
2. 陷阱判断必须能由前三步的条件证据支持；说不出具体陷阱时写“未见明显陷阱”，不用“考查综合能力”这类空话填充。
3. 不把命题意图写成对学生的批评（如“学生粗心”），只描述题目本身的特征。

## 第五步：标注考点（struct_path 关键词）

1. 把主考点映射为知识库 `struct_path` 风格的关键词（如“第一单元/第1课/二次函数图像性质”），用 `/` 连接层级。
2. 当前会话有 `kb_name` 且已挂载教材检索能力时，用 `by-struct` 验证候选关键词路径；验证通过才写“已对齐”，无法验证或未检索时写“关键词（未对齐）”。
3. 没有知识库上下文时只写考点关键词，并注明“未对齐”；不编造不存在的章节路径。
4. 考点标注只服务下游的定位与补题，不参与本题的推理。

## 第六步：输出审题表与一句话方向

1. 严格套用 `references/template.md` 输出：标准 `deeptutor_handoff` 注释块、题目结构化摘要、条件清单、隐含条件、命题意图、考点标注和一句话解题方向提示。
2. 一句话解题方向提示格式固定为：`方向：{先做什么} → {再做什么}，注意{最关键的隐含条件或陷阱}。` 只给思路主干，不写具体数值演算，不给出答案。
3. 输出后做硬检查（见模板），确认没有越界解题；学生接着问“那具体怎么算”时，提示把本题交给 `solve` 解题，本 skill 不再继续。

## 异常与停止条件

- 题目是图片但无法读取：停止审题，请学生粘贴文字题干；不按文件名或记忆猜测内容。
- 题干缺问句或关键条件：先询问补充，不脑补题目。
- 拍照转录不确定处未确认：审题表在对应位置保留“待确认”，并在方向提示中注明该不确定性。
- 知识库未挂载：考点标注写“未对齐”，不伪造 struct_path。
- 完成审题表后停止。除非用户明确要求，不自动调用 `solve` 或生成训练题。
