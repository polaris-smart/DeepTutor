# 丢分诊断器

把一张卷子的分数痕迹变成可追溯的修补顺序。诊断的张力在于“给出明确结论”与“不把分数猜成心理原因”：证据足够时果断归类，证据不足时保留“待确认”，不要用看似专业的错因填满表格。

开始后调用 `read_skill(name="score-diagnosis", file="references/template.md")`，把该模板当作 Markdown 输出合同。只有用户要求 A4 打印版时，再调用 `read_skill(name="pre-exam-checklist", file="references/print-css.md")` 读取并复用打印 CSS 骨架。

## 第一步：接收并规范判卷数据

1. 接收两类输入：
   - `quiz_judge` WebSocket 产物或其他结构化判卷结果；
   - 老师、学生口述或粘贴的逐题满分与得分。
2. 每题尽量保留下列字段：题号、真实 `q_id`、题型、知识点、知识类型、满分、得分、作答、参考答案、判卷反馈和已有错因。只使用输入中真实存在的 `q_id`；只有题号时写“题号 N”，不要伪造成 `q_id`。
3. 逐题计算 `丢分 = max(满分 - 得分, 0)`。核对“逐题满分合计 = 试卷满分”“逐题得分合计 = 总分”“逐题丢分合计 = 总丢分”；输入本身不一致时展示差额并标记“待核对”，不要暗自改数。
4. 缺少题型或知识点时保留“未提供”。缺少单题满分或得分而无法计算丢分时，把所有缺项合并成一次询问；用户无法补充时仍可整理已知题目，但不得给出声称覆盖整卷的 TOP3。
5. 同一题关联多个知识点时，优先采用输入提供的归因权重；没有权重时把该题丢分等分到所有已明确关联的知识点，并在统计口径写“多知识点题均分估算”。确保知识点维度丢分合计始终等于总丢分，不重复累计整题分值。

## 第二步：逐题诊断错因

`deeptutor/learning/models.py` 中的 `ErrorType` 与六维能力快照是两套独立语义：

- `ErrorType` 四类是 `structural`（知识结构性）、`deviation`（理解偏差型）、`application`（应用错误）、`metacognitive`（元认知型）。
- 六维能力键是 `knowledge`、`procedure`、`understanding`、`transfer`、`retention`、`habit`。六维结果只能作为补充证据，不能把某个维度名直接当成 `ErrorType`。

逐道丢分题同时给出用户易读错因与规范 `ErrorType`：

| 用户易读错因 | 典型证据 | 对应 `ErrorType` 的判断 |
| --- | --- | --- |
| 概念 | 前置知识缺口、定义或关系未建立 | 知识网络缺口用 `structural`；知识存在但理解偏移用 `deviation` |
| 计算 | 列式方向正确，但运算、符号、单位或代入出错 | 通常用 `application` |
| 审题 | 漏条件、看错要求、答非所问，且不是知识不会 | 通常用 `metacognitive` |
| 推理 | 论证链、迁移步骤或方法选择出现断点 | 理解链偏移用 `deviation`；理解正确但落地步骤错用 `application` |

执行规则：

1. 证据优先级依次为：老师或判卷器明确标签 → 可见作答与参考过程 → 具体判卷反馈 → 只有得分。只有得分不能证明错因。
2. 每道丢分题只能选一个主要易读错因和一个主要 `ErrorType`；多个因素并存时把次因写进证据说明，不重复计题或丢分。
3. 证据不足时，两列均写“待确认”，并给出最短确认问题，例如“是公式不会，还是代入后算错？”。不要根据题型刻板推断错因。
4. 满分题的错因与 `ErrorType` 均写“—”。零分但未提供作答时仍是“待确认”，不是自动判成“概念”。
5. 若输入带六维快照，只引用 `data_state: scored` 且有 `evidence_refs` 的维度结果；`insufficient` 不得包装成能力结论。

## 第三步：统计丢分分布

1. 按题型统计题数、满分、得分与丢分；没有题型的数据单列“未提供”。
2. 按知识点统计满分、得分与丢分，并列出关联 `q_id` 或题号。多知识点题遵循第一步的权重或均分口径。
3. 所有分值保留最多 1 位小数。两个维度各自的丢分合计都必须与总丢分一致；因缺数据无法守恒时显式列出“未归属丢分”，不要把它塞进某个知识点。
4. 报告中写清统计口径、缺失字段和任何估算；“未提供”“待确认”都是有效数据状态，不用模型猜测消除。

## 第四步：选出 TOP3 提分点

以“丢分多 × 可补救”为原则，对知识点与主要错因组合排序：

1. 先按证据判断可补救度：孤立的审题/计算失误且方法主体正确为高；局部理解偏差或应用链缺口为中；知识结构缺失、证据不足或依赖大量前置内容为低。
2. 在同一可补救度内先按丢分降序，再按涉及题目数降序。不要仅因“计算”这个标签就一律判高，也不要仅因“概念”就一律判低。
3. 最多输出 3 个提分点；不足 3 个有证据的候选时如实输出实际数量。
4. 每个提分点写“丢了什么分、为何可补、先做什么”，但不在本 skill 中承诺可回收分数；分数空间由下游 `potential-scanner` 评估。

## 第五步：按合同输出并接力

1. 严格套用 `references/template.md`，先输出标准 `deeptutor_handoff` 注释块，再输出题目明细、两个分布表、TOP3 和“接力数据”。
2. header 七个字段及顺序必须与 `pre-exam-checklist` 一致：`subject`、`textbook`、`scope`、`student`、`date`、`upstream`、`suggested_downstream`。缺失值写“未提供”，学生不明确时写“通用”。
3. `suggested_downstream` 固定为 `potential-scanner`。`upstream` 写真实来源，例如 `quiz_judge:<产物标识>` 或 `teacher_statement`；没有标识时不自造。
4. “接力数据”逐知识点给出满分、丢分、知识类型、当前掌握、关联题目和主要错因。它是下游稳定输入，不得省略；未知值保持“未提供”。
5. 用户要求 A4 打印版时，把同一份已核验数据转换为独立 HTML，不重新计算分数。完整内嵌 `pre-exam-checklist/references/print-css.md` 的 CSS，以 `.sheet` 为页面容器，并用 `exec` 写入新文件；文件已存在时改用日期或短范围名，不覆盖旧文件。返回执行结果中的 artifact 下载链接。

## 异常与停止条件

- 判卷结果只有总分、没有逐题得分：说明无法做逐题归因与二维分布，请用户补充逐题数据，不伪造诊断。
- 作答、反馈和错因均缺失：可以计算丢分分布，但逐题错因保留“待确认”，TOP3 明确为“仅按分值排序”。
- 题号、`q_id` 或知识点缺失：保留原始缺口；后续报告不得据此编造“做哪 3 题”。
- 完成 Markdown 诊断与接力数据后停止。除非用户明确要求，不自动运行 `potential-scanner` 或生成训练题。
